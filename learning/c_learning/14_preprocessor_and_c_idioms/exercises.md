# Chapter 14 — Exercises

Write each exercise as `ex14_K.c` in this folder (`ex14_1.c`, `ex14_2.c`, ...), plus any headers the
exercise asks for. Compile with `cc -Wall -Wextra -std=c11 -O2 -o ex14_K ex14_K.c -lm`. Zero warnings.
Use `cc -E` whenever you're unsure what a macro expands to.

---

### 14.1 — **Watch the preprocessor work**

Write a file with an object-like macro, a function-like macro, an `#ifdef DEBUG` block, `__FILE__`/`__LINE__`/`__func__`, and one `#include <stdio.h>`. Run `cc -E -P -std=c11 ex14_1.c | tail -30` and paste the expansion of *your* code (not stdio) into a comment. Then rerun with `-DDEBUG` and show the difference. Finally print the values of `__STDC_VERSION__`, `__DATE__`, and whether `__APPLE__`/`__aarch64__`/`__clang__` are defined.

<details><summary>Hint</summary>
Your code appears at the bottom of the `-E` output because stdio expands to thousands of lines first. Use `-dM` to list all predefined macros.
</details>

### 14.2 — **Macro hygiene lab**

Write `BAD_SQUARE(x) x*x`, `SQUARE(x)`, `BAD_MAX`/`MAX`, `BAD_SWAP`/`SWAP`. For each pair, construct a call that gives the *wrong* answer with the BAD version and print both results side by side with the expected value. Cases: `SQUARE(a + 1)`, `MAX(i++, j)` (print `i` afterwards), `if (c) SWAP(x, y); else puts("no")`. Then rewrite `MAX` as a `static inline` function and show `MAX(i++, j)` now increments `i` exactly once.

Example:
```
BAD_SQUARE(2+1) = 5   SQUARE(2+1) = 9   expected 9
after BAD_MAX(i++, j): i = 7 (expected 6)
```

<details><summary>Hint</summary>
`BAD_SWAP` without `do/while(0)` won't even compile in the `if/else` — capture the error message in a comment, then fix it.
</details>

### 14.3 — **`LOG` with levels and stringification**

Write `LOG(level, fmt, ...)` printing `[LEVEL file:line func] message` to `stderr`, where level is one of `LOG_DEBUG, LOG_INFO, LOG_WARN, LOG_ERROR` (an enum) and the level name comes from a string table. Add a compile-time `LOG_MIN_LEVEL` macro so calls below it compile to nothing (verify with `-E` that they vanish). Add `CHECK(cond)` that logs `ERROR` with the stringified condition and calls `abort()` if false.

Example:
```
[INFO ex14_3.c:31 main] epoch 3 loss 0.2311
[ERROR ex14_3.c:40 main] CHECK failed: a->cols == b->rows
```

<details><summary>Hint</summary>
`#define LOG(lvl, fmt, ...) do { if ((lvl) >= LOG_MIN_LEVEL) fprintf(stderr, "[%s %s:%d %s] " fmt "\n", log_names[lvl], __FILE__, __LINE__, __func__, ##__VA_ARGS__); } while (0)`. When `lvl` is a constant below the threshold, `-O2` removes the dead `if`; with `-E` you'll still see the text — to make it *vanish* at preprocessing time you need separate macros per level guarded by `#if`.
</details>

### 14.4 — **X-macro op table** (ML)

Define `OP_LIST(X)` with entries `(OP_ADD, "add", 2), (OP_MUL, "mul", 2), (OP_NEG, "neg", 1), (OP_TANH, "tanh", 1), (OP_MATMUL, "matmul", 2)` where the third field is arity. Generate: the `Op` enum with `OP_COUNT`, `op_names[]`, `op_arity[]`, and `Op op_from_name(const char *)`. Print a table of all ops. Then add `OP_RELU` by editing only the list and show the table grew. Finally, write a `switch (op)` with a `case` for every op generated by the X-macro too (`#define AS_CASE(id, name, ar) case id: puts(name); break;`).

Example:
```
 0  add     arity 2
 1  mul     arity 2
 ...
op_from_name("tanh") = 3
```

<details><summary>Hint</summary>
Each generated table needs its own `AS_*` macro and `#undef` after. `op_from_name` returns `OP_COUNT` when not found.
</details>

### 14.5 — **Header-only `rng.h`**

Turn your chapter-12 RNG into a header-only library `rng.h` (stb style): declarations + `static inline` `rng_uniform`, definitions of `rng_seed`/`rng_gaussian` behind `#ifdef RNG_IMPLEMENTATION`. Write `ex14_5.c` that defines the macro and includes it, and `ex14_5b.c` that includes it *without* the macro and calls `rng_gaussian`. Compile both into one binary: `cc ... ex14_5.c ex14_5b.c -lm`. Then deliberately define `RNG_IMPLEMENTATION` in both and paste the linker error into a comment.

<details><summary>Hint</summary>
The implementation block goes *outside* the include guard. `ex14_5b.c` needs a non-static function declared in the header to call from `main` in `ex14_5.c` (e.g. `double sample_from_b(void)`).
</details>

### 14.6 — **Error enum + `goto cleanup`**

Define `Err` via an X-macro (`ERR_OK, ERR_ALLOC, ERR_IO, ERR_PARSE, ERR_SHAPE`) with `err_str()`. Write `Err load_matrix_csv(const char *path, Matrix **out)` that opens a file, allocates a line buffer, allocates a `Matrix`, parses rows of comma-separated doubles (use `strtod`, check `errno`), and returns the appropriate `Err` for: missing file, malformed number, inconsistent row length, allocation failure. Use a single `cleanup:` label. Test every failure path with small files you create in `main` (write them with `fopen`/`fprintf` first) and run under `leaks --atExit` to prove nothing leaks on any path.

Example:
```
good.csv     -> ok (3x2)
missing.csv  -> I/O error: No such file or directory
bad_num.csv  -> parse error (line 2)
ragged.csv   -> shape mismatch (line 3 has 3 fields, expected 2)
```

<details><summary>Hint</summary>
Initialize every resource pointer to `NULL` before the first `goto`. Set `*out = m; m = NULL;` on success so the shared cleanup doesn't free the result. Record the line number in a variable so the message can include it.
</details>

### 14.7 — **Opaque `Tensor` with const-correct API**

Split into `tensor.h` (incomplete `typedef struct Tensor Tensor;` and function declarations) and `tensor.c` (the struct definition and implementations): `tensor_new(ndim, shape)`, `tensor_free`, `tensor_numel(const Tensor *)`, `tensor_shape(const Tensor *, size_t dim)`, `tensor_data(Tensor *)`, `tensor_cdata(const Tensor *)`, `tensor_fill`, `tensor_sum(const Tensor *)`. In `ex14_7.c` show that `t->data` is a compile error (paste the message in a comment), that `tensor_fill` through a `const Tensor *` is a compile error, and that the program works via the API. Use designated initializers and a compound literal for the shape: `tensor_new(2, (size_t[]){ 3, 4 })`.

<details><summary>Hint</summary>

### 14.8 — **`Config` structs as keyword arguments** (ML)

Define `typedef struct { double lr; double momentum; int epochs; int batch_size; const char *optimizer; unsigned seed; } TrainConfig;` and a `TRAIN_CONFIG_DEFAULTS` compound literal macro. Write `void train(const TrainConfig *cfg)` that prints the effective config. Call it four ways: all defaults; `&(TrainConfig){ .lr = 0.1 }` (note what happens to the other fields — zero, not defaults!); a `TrainConfig c = TRAIN_CONFIG_DEFAULTS; c.lr = 0.1;` override; and a helper macro `TRAIN(...)` that merges overrides into defaults. Explain in comments why the second call is a trap and the third/fourth are the idiom.

<details><summary>Hint</summary>
`#define TRAIN_CONFIG_DEFAULTS ((TrainConfig){ .lr = 0.01, .momentum = 0.9, .epochs = 10, .batch_size = 32, .optimizer = "sgd", .seed = 42 })`. Merging can be done with a function `train_config_with(TrainConfig base, TrainConfig overrides)` that copies non-zero fields.
</details>

### 14.9 — **Declaration decoder**

Write a program that declares each of these (with real functions where needed so it links) and uses each correctly at least once, with a comment reading each aloud: `char *argv[]`; `char (*row)[16]`; `double (*mat)[4]` pointing at a `double m[3][4]` and indexed `mat[i][j]`; `int (*cmp)(const void *, const void *)`; `void (*handlers[3])(int)`; `void (*install(int, void (*)(int)))(int)` (your own function with `signal`'s shape that stores the handler in a table and returns the previous one); then the same `install` declared via a `typedef`. Call `install` twice and show it returns the previous handler.

<details><summary>Hint</summary>
Read from the identifier outward: right for `[]`/`()`, left for `*`, parentheses first. `cdecl` can check your readings.
</details>

### 14.10 — **Parallel matmul with OpenMP and pthreads** (numerics / sims)

Take your `ikj` matmul from chapter 13. Version A: add `#pragma omp parallel for` on the outer loop; compile with and without `-Xpreprocessor -fopenmp -lomp` (`brew install libomp`; on Linux `-fopenmp`) and time 1024×1024 both ways. Version B: the same parallelization with `pthread`: split rows across `T` threads using a `Job` struct and `pthread_create`/`pthread_join`. Verify all three (serial, OpenMP, pthread) agree to `1e-9`. Print a table of time and speedup for `T ∈ {1, 2, 4, 8}` (use `omp_set_num_threads` / your own `T`). Then compute Amdahl's predicted speedup assuming the serial fraction is the time spent in initialization + verification, and compare.

Example:
```
serial ikj          1024   0.121 s
openmp  8 threads          0.019 s   6.4x
pthread 8 threads          0.021 s   5.8x
```

<details><summary>Hint</summary>
Each thread writes its own rows of `C` → no race, no locks. Guard the OpenMP-specific calls with `#ifdef _OPENMP` (defined by the compiler only when `-fopenmp` is active) so the source compiles either way.
</details>
